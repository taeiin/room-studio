# 내 웹사이트로 배포하기

이 저장소는 **개발 중인 프로젝트**입니다. 저장소를 복제하면 로컬에서 실행할 수 있지만, 그 자체로 웹사이트가 공개되거나 자동 배포되지는 않습니다. 현재 코드에는 독립 배포용 설정과 사용자별 서버 저장이 완성되어 있지 않으므로, 아래 순서대로 Codex와 함께 준비하세요.

## 준비할 것

- GitHub 계정과 본인이 수정할 수 있는 저장소: 원본 저장소를 fork하거나 쓰기 권한을 받습니다.
- PC의 Git, Node.js 22.13 이상과 Codex 앱.
- 배포할 호스팅 계정. 아래는 Cloudflare Workers를 검토하는 예시이며 다른 호스팅도 가능합니다.
- 무료 요금제의 사용량과 제한 확인. 모든 사용이 무제한 무료인 것은 아닙니다. [Cloudflare Workers 요금 안내](https://developers.cloudflare.com/workers/platform/pricing/)와 [빌드 사용량 안내](https://developers.cloudflare.com/workers/ci-cd/builds/limits-and-pricing/)를 확인하세요.

## 1. 내 저장소를 받고 실행하기

GitHub에서 원본 저장소를 fork한 다음, 내 저장소의 주소를 사용해 복제합니다. 아래 주소는 자신의 GitHub 이름으로 바꿉니다.

```bash
git clone https://github.com/내-아이디/room-studio.git
cd room-studio
npm ci
npm run dev
```

터미널에 표시되는 로컬 주소에서 도면 화면이 열리는지 확인합니다. `npm run build`는 빌드 점검 명령이며, 이것만으로 배포되지는 않습니다.

## 2. Codex에서 배포 준비하기

Codex 앱에서 방금 복제한 폴더를 열고 다음을 요청합니다.

> 이 저장소를 내 GitHub 계정과 Cloudflare 계정으로 독립 배포할 수 있게 도와줘. 먼저 README.md, AGENTS.md와 docs/배포-가이드.md를 읽어줘. 현재 코드의 빌드·배포 설정과 Sites 전용 인증 및 저장소 의존성을 확인하고 공개 서비스에서 안전한 구조로 수정해줘. 기존 Sites의 project_id는 재사용하지 마. 무료로 시작할 수 있는 한도와 제약을 설명하고, 비용이 발생하는 선택은 내가 결정할 수 있게 해줘. 필요한 설정을 준비해 로컬 빌드를 검증하고, 내가 직접 로그인하고 계정을 연결할 수 있도록 화면 순서대로 안내해줘. 비밀번호나 API 키를 채팅이나 Git에 적게 하지 마. 배포 후 공개 주소에서 도면 업로드, 방 지정, GLB 가구 등록·배치와 백업을 검증해줘. 사용자별 서버 저장이 없으면 기기별 저장임을 알려줘.

이 프로젝트의 기존 `app/api` 라우트는 Sites 전용 인증 헤더와 D1/R2 바인딩에 의존합니다. Cloudflare에 저장소만 연결하면 자동으로 안전하게 동작하는 구성이 아닙니다. Codex가 먼저 **서버 인증을 안전하게 교체하거나 해당 라우트를 배포 대상에서 제외**하고, 빌드 결과와 배포 설정을 실제로 검증해야 합니다. `.openai/hosting.json`의 기존 `project_id`도 원본 사이트용입니다.

## 3. GitHub와 호스팅 연결하기

Codex가 배포 설정을 준비하고 빌드가 통과한 후, Cloudflare를 선택했다면 대시보드에서 다음 흐름으로 진행합니다.

1. [Cloudflare 대시보드](https://dash.cloudflare.com/)에 로그인하고 **Workers & Pages**로 이동합니다.
2. **Create application**에서 GitHub 저장소 연결을 선택합니다. 처음 연결할 때 GitHub 권한 승인 화면이 나타날 수 있습니다.
3. 내 fork 저장소와 배포할 브랜치를 선택합니다. Codex가 검증한 빌드·배포 설정을 입력합니다. 이 저장소는 아직 범용 배포 설정이 완성되지 않았으므로 임의의 명령을 복사해 사용하지 마세요.
4. 배포를 실행하고 로그와 제공된 `workers.dev` 주소를 확인합니다. 화면의 메뉴 이름은 서비스 업데이트에 따라 달라질 수 있습니다. [Cloudflare 공식 연결 절차](https://developers.cloudflare.com/workers/ci-cd/builds/)를 참고하세요.

로그인·권한 승인과 결제 관련 선택은 본인이 직접 처리합니다. 비밀번호, 인증 코드, API 키는 채팅이나 Git 저장소에 넣지 않습니다.

## 4. 실제 사용자 흐름 확인하기

공개 주소에서 직접 다음을 시험합니다.

- 빈 프로젝트가 열리고 도면을 업로드·보정해 3D로 볼 수 있는지.
- Codex 앱에서 별도로 만든 GLB를 등록해 방에 배치·이동·회전할 수 있는지.
- 백업 내려받기와 불러오기로 도면·가구를 복원할 수 있는지.
- 각 사용자 브라우저의 데이터가 다른 사용자 화면에 자동으로 나타나지 않는지.

현재 저장은 **각 브라우저에만** 되며, 사용자 계정과 서버 동기화는 미구현입니다. 여러 기기에서 같은 데이터를 사용하려면 백업 파일을 직접 옮겨야 합니다. 서로 다른 계정으로 서버 저장을 제공하려면 별도의 인증·저장 기능을 개발하고 접근 통제를 검증해야 합니다.

## 5. 이후 변경사항 배포하기

Codex가 GitHub 자동 배포를 정상 구성한 경우, 연결된 브랜치에 변경사항을 push하면 호스팅에서 빌드가 시작됩니다. GitHub와 Cloudflare의 빌드 로그 및 공개 주소를 확인하세요. **GitHub push가 성공한 것과 웹 배포가 성공한 것은 다릅니다.** 연결이 없는 현재 상태에서는 push해도 웹이 업데이트되지 않습니다.
