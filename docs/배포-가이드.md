# 내 웹사이트로 배포하기

현재 제공하는 공개 빌드는 도면과 가구를 **사용자의 브라우저에만 저장**합니다. 로그인, 사용자별 서버 저장과 기기 간 자동 동기화는 제공하지 않습니다. 데이터 이전은 웹의 백업 내려받기·불러오기로 합니다.

공개 빌드에서는 이전 Sites 전용 `/api`와 로그인 경로를 차단하고 D1/R2 연결을 제거합니다. 따라서 이 버전을 배포하는 데 기존 Sites 계정이나 API 키는 필요하지 않습니다. 저장소의 기존 다은마을 도면과 모델 파일은 공개 자산으로 포함됩니다.

## 준비물

- GitHub 계정과 이 저장소의 fork. [원본 저장소](https://github.com/taeiin/room-studio)에서 **Fork**를 선택합니다.
- 무료로 시작할 수 있는 Cloudflare 계정. 무료 사용량과 제한은 변할 수 있으므로 [Workers 요금](https://developers.cloudflare.com/workers/platform/pricing/)과 [빌드 한도](https://developers.cloudflare.com/workers/ci-cd/builds/limits-and-pricing/)를 연결 전에 확인하세요.
- 로컬 시험 시 Git과 Node.js 22.13 이상. Codex 앱은 가구 제작과 설정 도움에 사용할 수 있습니다.

## 1. 내 PC에서 배포용 빌드 시험

GitHub에서 만든 본인 fork의 주소를 사용합니다.

```bash
git clone https://github.com/내-아이디/room-studio.git
cd room-studio
npm ci
npm run build:public
npm run check:public
```

`check:public`은 실제로 배포하지 않는 Cloudflare 사전 검사입니다. 빌드가 실패하면 출력을 Codex 앱에 전달해 해결하세요. API 키나 비밀번호는 전달하지 마세요.

기본 Worker 이름은 `room-studio`입니다. 같은 Cloudflare 계정에 동일한 이름이 이미 있으면 이름이 충돌할 수 있습니다. 고유한 이름이 필요하면 빌드 환경 변수 `ROOM_STUDIO_WORKER_NAME`을 영문 소문자·숫자·하이픈으로 설정하고, Cloudflare의 Worker 이름도 정확히 같게 설정하세요.

## 2. Cloudflare에 GitHub 저장소 연결

1. [Cloudflare 대시보드](https://dash.cloudflare.com/)에서 로그인 후 **Workers & Pages → Create application**으로 이동합니다.
2. GitHub 연결을 선택하고 본인의 fork 저장소에 대한 연결 권한을 직접 승인합니다.
3. Worker 이름을 기본값인 `room-studio`로 지정합니다. 다른 이름을 쓰면 위 환경 변수도 동일하게 맞춥니다.
4. Git 연결과 빌드 설정을 지정할 수 있는 화면에서 다음을 입력합니다.
   - **Build command:** `npm run build:public`
   - **Deploy command:** `npm run deploy:public`
   - **Production branch:** 보통 `main`
5. 배포를 진행하고 빌드 로그와 발급된 `workers.dev` 주소를 확인합니다.

메뉴 이름과 화면은 Cloudflare 변경에 따라 달라질 수 있습니다. 공식 [Workers Builds 절차](https://developers.cloudflare.com/workers/ci-cd/builds/)와 [빌드 설정](https://developers.cloudflare.com/workers/ci-cd/builds/configuration/)도 확인하세요. 저장소 의존성 설치가 자동 실행되지 않는 환경에서는 빌드 명령을 `npm ci && npm run build:public`으로 설정합니다.

**실제 Cloudflare 계정으로 배포하는 단계는 아직 이 저장소에서 실증하지 않았습니다.** 계정 권한이나 호스팅 정책에 따라 추가 설정이 필요할 수 있습니다. 로그인, 권한 승인과 비용 관련 선택은 본인이 직접 처리하고 비밀번호·인증 코드·API 키를 채팅이나 Git에 넣지 마세요.

## 3. 공개 주소에서 확인

- 빈 프로젝트가 열리고 도면 업로드, 방 지정·수정과 3D 미리보기가 되는지 확인합니다.
- Codex 앱에서 별도로 만든 GLB를 등록하고 방에 배치·이동·회전합니다.
- 백업 내려받기와 불러오기로 도면과 가구를 복원합니다.
- 서로 다른 브라우저에서는 데이터가 자동 동기화되지 않는지 확인합니다.

도면 자동 감지는 실험 기능이며 오탐과 누락이 발생합니다. 각 후보와 치수를 직접 확인해야 합니다. 사용자 계정·서버 저장을 새로 추가하려면 검증된 인증과 사용자별 접근 통제, 업로드 보안을 별도로 구현해야 합니다. 기존 Sites 인증 헤더를 외부에서 검증 없이 신뢰하지 마세요.

## 4. 이후 업데이트

Cloudflare에 GitHub 저장소와 브랜치를 성공적으로 연결했다면 해당 브랜치에 push할 때 빌드와 배포가 시작됩니다. GitHub push가 성공한 것만으로 배포 성공을 뜻하지 않으므로 Cloudflare의 빌드 결과와 실제 주소를 확인하세요.

## Codex에 도움 요청하기

> 이 저장소의 README.md와 docs/배포-가이드.md를 읽고 `npm run build:public` 및 `npm run check:public`을 실행해 줘. 내 Cloudflare Worker 이름과 GitHub fork 연결을 화면 순서대로 도와줘. 비용이 드는 설정은 먼저 설명하고, 비밀번호·인증 코드·API 키를 채팅이나 Git에 적게 하지 마. 실제 배포 후 공개 주소에서 도면 업로드, 방 지정, GLB 등록·배치와 백업을 확인해 줘.
